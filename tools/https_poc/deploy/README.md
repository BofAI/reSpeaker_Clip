# 单设备公网验证部署

复用现有 `server.py` / `resume_store.py` 协议与落盘机制，部署入口为
`run_receiver.py`。只使用 Python 标准库，支持 TLS 1.2 及以上；同时最多 16 个
连接，连接握手及读写超时沿用接收端的 15 秒限制。不启动实验用 SNTP 服务。

这是受控验证服务，尚未实现多用户、管理界面、配额、备份或生产级监控。
每个数据目录只能运行一个接收进程；不能共享目录启动多个实例。

## 目录及服务

```text
~/clip-receiver/
  app/server.py
  app/resume_store.py
  app/run_receiver.py
  private/server.key          # 服务器本机生成，不进入源码库
  private/server-chain.pem    # 叶证书及签发链
  private/token               # 设备 Bearer 令牌
  data/                      # 文件及持久检查点
~/.config/systemd/user/clip-receiver.service
```

安装目录及 private/data 权限为 0700，私钥及令牌为 0600。源码和凭据分别同步；
不得同步开发机整个 private 目录，也不传输 Wi-Fi 密码或 CA 私钥。

服务模板使用 `clip-c7bb`、TCP 9527，其他设备部署前须调整 `--device`。
私钥必须匹配证书，叶证书 SAN 必须覆盖设备配置的 IP 或域名，签发链必须受
设备固件中 CA 信任；不能关闭证书或主机名校验。证书应在到期前替换。

```sh
loginctl enable-linger "$USER"
systemctl --user daemon-reload
systemctl --user enable --now clip-receiver.service
systemctl --user status clip-receiver.service
journalctl --user -u clip-receiver.service
```

`Linger=yes` 与单元 `enabled` 同时满足才具备未登录时的开机启动条件。
云网络必须另外允许 TCP 9527；systemd 不会修改安全组或系统防火墙。
停止接收可执行 `systemctl --user stop clip-receiver.service`，不删除数据。

## 设备公网验证

在不刷机的情况下，设备保留已存 Wi-Fi，仅更新接收地址、设备令牌及校时配置。
未通过 USB 注入 TLS 时间；修改校时地址后 `time_ready=false`，上传后变为 true，
设备实际完成公网 SNTP、TLS 及上传。三段新建测试录音均与服务器长度及 SHA-256
一致，且本地状态为 uploaded、目标指纹匹配：

| 会话 / 片段 | 字节数 | 结果 |
|---|---:|---|
| 20261021084621 / 1 | 40,932 | 首次公网上传约 18.47 秒，含联网和校时等阶段 |
| 20261021084913 / 1 | 69,917 | 确认 16,384 字节后被新录音抢占，随后从该偏移续传完成 |
| 20261021084946 / 1 | 16,093 | 抢占后新录音正常保存并上传 |

START 请求到实际进入普通录音约 463 毫秒。第一段和最后任务后系统堆占用均为
1,656 字节，当前启动中观测峰值 44,224 字节，不是整机最坏值。中断测试的恢复
通过手动 UPLOAD 触发；本轮没有开启自动队列，不将它当作公网自动恢复专项验收。
原录音未删除，未改设备固件；尚未测试公网增强录音抢占和完整队列耗尽。

## 公网自动上传与速率采样

开启前扫描到 83 个可上传片段，其中 80 个需要向当前目标上传。仅发送一次
`UPLOADAUTO=on`，观察程序不发送手动 UPLOAD。前 5 个任务全部成功，采样结束
时 enabled/config_saved 均为 true、paused=false、failures=0，开关保持开启。
随后服务器文件数从初始 4 增至 11，说明在五次采样后队列仍继续工作。

| 文件字节数 | 整次任务秒数 | 传输阶段秒数 | 传输阶段 KiB/s |
|---:|---:|---:|---:|
| 44,795 | 21.76 | 5.93 | 7.38 |
| 18,758 | 16.34 | 2.83 | 6.46 |
| 118,206 | 32.31 | 15.48 | 7.46 |
| 87,850 | 31.56 | 15.71 | 5.46 |
| 52,844 | 22.23 | 7.49 | 6.89 |

合计 322,453 字节。按总字节/总耗时计算：传输阶段约 **6.64 KiB/s**，
整次任务约 **2.54 KiB/s**；从开关开启到第五个任务完成（包含首次等待和
文件间调度）约 149.67 秒，队列吞吐约 **2.10 KiB/s**。

传输阶段从第一次观察到 sending/verifying 起计至成功；USB 每约 0.25 秒轮询，
因此是应用层粗粒度估算，不是网卡线速，不含 TLS/TCP 包头。任务开始前的扫描
不计入单任务计时。每次任务在传输前约 13.5–16.8 秒，包含准备、联网及 TLS 等；
它们加上约 5 秒文件间调度，对小文件吞吐影响明显。这批是既有测试录音，不能
直接当作长录音的吞吐或所有网络条件的性能上限。完整队列耗尽尚未观察完成。

## 滚动窗口连接复用支持

服务端已部署 `X-Clip-Batch: 1` 的跨文件连接保留支持，未带该头的客户端维持
原关闭行为。公网合成测试在同一条经校验的 TLS 1.2 连接内完成三份 20,017 字节
文件，均通过长度和 SHA-256 确认。源码回退文件为
`~/clip-receiver/backups/server-before-batch.py`；回退只替换服务代码并重启单元，
不删除 data 或 private。

设备侧滚动窗口优化仍需刷机后验证。停止旧版队列时，最后文件为 574,179 字节，
服务端已确认前缀为 425,984 字节；自动上传关闭状态已持久保存。既有文件和检查点
保留，未为了优化清空服务器数据或设备录音。

设备迁移需更新接收端 host/port，并使用可达的 SNTP 地址；公网服务未启动
原 Mac 的 UDP 12345 校时端点。接收地址变化会改变本地上传目标指纹，可能使
旧录音被重新发现为待传，切换前需明确是否迁移旧服务器数据。
