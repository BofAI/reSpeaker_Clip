# 上传状态持久化验证

本阶段增加设备 SD 上的单片段 HTTPS 状态，不修改手机同步标记。上传和续传由 USB
命令触发；空闲自动扫描、自动重试和配置持久化尚未接入。

## 实机结果

| 场景 | 结果 |
|---|---|
| 从未尝试上传的旧录音 | pending，无有效本地记录 |
| 完整上传 | uploaded，长度、内容摘要和接收端身份匹配 |
| 普通／增强录音打断上传 | partial，已确认 16,384 字节；录音结束后可续传 |
| partial 状态后重启 | 状态和偏移保留，重新配置后从服务器确认的 16,384 继续 |
| uploaded 状态后重启 | 完整上传标记保留，所有查询字段与重启前一致 |
| 错误回执偏移 | confirmed 不前进，记录 failed；修正接收端后可续传 |
| 接收端端口改变 | 旧记录有效，但目标不匹配，当前状态显示 pending |
| 手机同步元数据 | 原参考录音的 AT+LIST 返回值在测试前后完全相同 |

参考录音 60,975 字节，SHA-256 为
`4a8f18cbeeb2c000fed1a6b7d01ba505463ee7aa59e29184491182667c4de8f5`。
普通和增强场景续传完成后的文件均与原件逐字节一致；两份新录音上传后分别解码
167／173 帧 Opus，时长 3.34／3.46 秒。START 发出至轮询检测到采集分别约
603／736 毫秒，包含串口和轮询误差，不代表最差时延保证。

两次重启均经已验证的 Recovery 入口执行 reset，没有再次刷写或擦除分区。
这验证正常重启后的持久状态，不代表物理断电或 SD 介质故障验证。
每次恢复都重新配置了易失的网络、接收端和时间；接收端也重新实例化并从磁盘
检查点恢复。接收成功但本地状态未保存的异常仍必须重新查询服务器。

## 主机与构建验证

80 项主机测试通过。新增测试直接编译 C 状态模块，使用 ASan／UBSan 与文件系统
故障注入，覆盖短写、同步／关闭失败、槽损坏回退、两槽损坏重建、代数回绕、
无效字段拒绝，以及目标／长度不匹配和忙状态查询拒绝。它们不替代物理掉电测试。

构建为零 C 编译器警告，签名校验通过。相对 `91c3d23`：

- Flash 增加 2,184 字节，使用 820,308，剩余 113,068 字节。
- 静态 RAM 使用 448,374 字节，净变化为零，包含既有堆栈预留。
- 分区和外置 Wi-Fi 固件保持一致；配置差异只有独立源码目录的签名密钥路径。

录音结束后系统堆均恢复 1,200 字节；增强录音所在启动周期测得堆峰值 68,504 字节。
最后一次重启后的 HTTPS 线程栈峰值为 5,640/8,192 字节，尚余 2,552 字节；
这些是对应采样周期的观测，不覆盖所有内存池和未来工作负载。

MCUboot 摘要为 `6c4bd0610ab2cdefb97d7c05f17163274d1de13139a18ad2ac927792e57f39d3`，
刷后和两次重启前均回读一致。构建记录及产物保存在本机
`.analysis/https-runtime-0.1.2/upload-state-v1/`，实测结果在
`upload-state-hardware-v1/` 及对应私有目录。首次刷写进程在读取旧镜像时被终止，
尚未执行镜像上传；随后重新核对旧摘要，完成刷写和整套测试。
