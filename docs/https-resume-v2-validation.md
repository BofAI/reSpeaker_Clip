# 文件内续传验证记录

基于 v0.1.2，普通与增强录音分别完成当前块中断、块回执丢失和最终回执丢失三种
场景，共六次录音抢占。每次停止录音后更换接收实例，从磁盘重读检查点，再通过
USB 命令重新发起同一文件上传；不是自动调度，也没有做设备掉电测试。

原文件 60,975 字节，续传结果如下；每种情况都分别测试了普通和增强录音：

| 中断时机 | 设备原先确认 | 服务器实际保存 | 下次续传起点 | 实际补发数据 |
|---|---:|---:|---:|---:|
| 当前块尚未完整接收 | 16,384 | 16,384 | 16,384 | 44,591 字节 |
| 块已保存、回执未送达 | 16,384 | 32,768 | 32,768 | 28,207 字节 |
| 文件已发布、最终回执未送达 | 49,152 | 60,975 | 60,975 | 0 字节 |

续传请求的起点和各块长度均由 Mac 测试接收端记录，最终文件与已知原件逐字节一致，
SHA-256 为 `4a8f18cbeeb2c000fed1a6b7d01ba505463ee7aa59e29184491182667c4de8f5`。
六份抢占后产生的新录音也均通过 v2 上传并逐帧 Opus 解码。
START 发出至轮询检测到采集的时间为 0.47–0.73 秒，含串口与轮询误差，不能外推
为最差时延。停止后堆占用均恢复 1,200 字节；本轮堆峰值 68,504 字节，HTTPS
线程栈峰值 5,552/8,192 字节。统计不覆盖全部独立内存池和未来所有工作负载。

另将块回执偏移故意从 16,384 改为 16,385：设备拒绝该回执，confirmed 未前进。
下一次从接收端真实的 16,384 检查点继续，最终内容一致。

主机共 72 项测试通过，覆盖 v1 兼容、TLS 连接复用、重复块、身份冲突、错误块哈希、
截断请求和设备回执边界。落盘故障注入覆盖数据写入后检查点失败、检查点重命名后
目录同步失败、最终发布前后中断，以及未确认尾部截断。它们不是物理断电验证。

最初实测的前两项已通过，但测试收尾等不到 keep-alive 工作线程退出；随后接收端
改为最终 stored 回执关闭连接、部分块保持连接，并重跑全部六项通过。旧记录保留。
所有数据及检查点文件均以私有权限创建，测试录音保留。

构建为零 C 编译器警告，签名和分区校验通过。相对 `1d5038b`，Flash 增加 672 字节，
静态 RAM 增加 16 字节；Flash 使用 818,124 字节，剩余 115,252 字节，静态 RAM
使用 448,374 字节（包含既有堆栈预留）。分区、外置 Wi-Fi 固件和配置参数未改变。

MCUboot 摘要为 `f3203e072f77d58f1f2f46f53db126f827b7b08a95d2332dc2d9bd2eec6c4936`，
刷后设备回读一致。固件源码与构建快照一致；构建后的接收端、测试和文档调整另存
主机源码快照。完整产物与源码记录位于本机 `.analysis/https-runtime-0.1.2/resume-v1/`，
