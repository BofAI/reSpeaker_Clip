# 设备端 HTTPS 上传状态

每个录音片段独立记录 HTTPS 状态，不修改 `session.json` 的手机同步 `synced`。
接收端仍是续传偏移的权威来源；设备持久记录用于识别待上传／已上传文件和显示
上次结果，不能直接把本地偏移当作下一次 HTTP 起点。

## 状态与身份

- `pending`：没有匹配记录、任务开始后未确认数据，或无进展时被录音取消。
- `partial`：至少一块收到有效回执，但文件尚未确认完整。
- `uploaded`：完整 stored 回执的总长度、内容 SHA-256 和最终偏移均验证通过。
- `failed`：尝试失败且没有已验证的进展；失败后的部分进展仍以 partial 表示。

记录绑定片段总长度、完整内容 SHA-256 和接收端指纹。接收端指纹由 host、port、
device ID 和编入固件的 CA 计算，不包含 Wi-Fi 密码或 Bearer 令牌；令牌轮换本身
不会改变目标身份。不同接收端的已上传标记不能直接用于当前目标。

任务先持久写 pending，再开始联网；退出时更新结果和最近确认偏移。不按每块回执
写 SD，因此非正常重启可能保留 pending 或较旧进展；再次上传仍会重新查询服务器，
恢复已落盘的检查点。数据保留成功但设备本地状态写失败时，不能依赖本地清单跳过任务。

## SD 记录格式

每个片段在所属会话目录中使用 `http-N.a`／`http-N.b` 两个 96 字节记录槽。记录含
版本、递增代数、长度、状态、错误码、内容与目标指纹以及 CRC32，小端编码。
更新时保留最新有效槽，只截断并写另一个槽，fs_sync、关闭后返回；不依赖 FAT
重命名的原子性。读取时检查长度、版本、字段一致性和 CRC，选择最新有效代数。
损坏的最新槽可回退到旧槽；两槽均无效时不报告 uploaded，允许下次任务重建记录。

CRC 用于检测破损，不是防篡改认证；双槽也不能保证 FAT 目录或物理介质掉电不坏。
真实断电、长期反复写和介质故障仍需单独验证。SD 状态读写复用已有会话元数据锁，
不新增线程或永久状态缓存；网络操作不持有该锁。

## USB 查询

配置接收端后，空闲时执行 `AT+UPLOADSTATE=YYYYMMDDHHMMSS:片段号`，返回标准
`ok/data` JSON，含 session、segment、state、size、confirmed、last_error、state_valid、
destination_match、size_match、state_error 和已记录 sha256。

`state_valid` 只表示记录格式与 CRC 有效；目标或长度不匹配时当前目标状态视为 pending。
查询基于已封口片段的不可变约定，只核对文件存在和大小，不在 AT 线程重读整个录音。
sha256 是上次上传时计算的摘要；新任务会重新计算内容摘要。离线改写同长度文件须
重新发起上传，不能把旧清单当作当前文件内容已重新验证。

缺失记录返回 pending；两槽破损时额外返回 state_error，实际 SD I/O 错误直接失败。
上传、待启动录音或录音进行中拒绝该查询。`AT+UPLOAD?` 另增 state_error，区分最后
一次本地状态保存失败与网络结果。原手机 SDK 同步标记和普通固件协议保持原状。
状态 I/O 出错时，无法确认句柄已安全清理，不启动排队录音，并通过 record_error
返回失败；不能用一个成功的网络回执掩盖本地 SD 故障。

目前只增加单片段持久状态与查询；自动扫描、空闲调度、分页状态列表及凭据持久化
按后续阶段接入。设备重启后需重新配置接收端，才能判断该目标下的状态。
