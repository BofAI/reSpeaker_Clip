# HTTPS 上传的录音抢占验证

受控实机测试中，普通、增强模式各完成两轮联网、TLS 握手、发送正文和等待回执阶段的抢占，共 16 次。每次均在上传资源清理后开始录音，新文件上传成功并逐帧 Opus 解码通过。此结果覆盖 USB `AT+START`，不代表自动上传、断点续传或长期稳定性已完成。

## 问题与修复

原 SDK 的 TLS `connect()` 即使配置非阻塞仍会阻塞握手；跨线程 `shutdown()` 需要取得同一个 socket 锁，不能及时中断它。原 HTTP 客户端等待响应时也未定期检查录音取消标志。仅把取消操作放到系统工作队列不能解决这些阻塞。

现在由上传线程独占原始非阻塞 TCP、mbedTLS 和文件，其他线程只设置取消标志。TCP、握手、收发等待按最多 50 毫秒切片检查取消，退出后由原线程统一清理。HTTP 仍使用 SDK 的增量解析器，有界接收并校验状态、长度和 SHA-256 回执。证书链、主机名、有效期和安全随机数校验保留。

50 毫秒是网络等待切片，不是录音启动上限；DNS、密码运算、Wi-Fi 关闭、震动提示与音频初始化仍影响总时延。

## 实测切换时间

从 Mac 发出 START 至轮询检测到 `recording:true`，包括串口和轮询误差，并非麦克风首个采样的硬件时间。新版本每个阶段四个样本，覆盖两种录音模式。

| 打断阶段 | 原版本样本 | 修复后样本范围 |
|---|---:|---:|
| 联网 | 0.87–0.96 秒 | 0.80–1.13 秒 |
| TLS 握手阻塞 | 10.35–10.63 秒 | 0.46–0.70 秒 |
| 正文发送 | 0.45–0.62 秒 | 0.52–0.75 秒 |
| 等待 HTTP 回执 | 35.52–35.71 秒 | 0.48–0.76 秒 |

握手测试接收端不执行 TLS 握手；等待回执测试则已持久化全部文件但暂缓响应。原版本约 35 秒的样本依赖测试接收端自动解除阻塞，不能当作固件取消上限。修复后在接收端放行之前即可开始录音。样本量有限，表中范围不能外推为最差上界。

## HTTPS 和异常响应检查

- 不可信 CA、错误 SAN、尚未生效和过期证书：设备均在握手阶段拒绝，接收端未收到 HTTP PUT。
- 错误哈希回执、截断正文和超长正文：均失败，未报告上传成功。
- 接收端保持无响应：约 15.05 秒后超时退出，随后资源恢复。
- 分块响应和失败后的正常重传：成功，落盘内容与原始 60,975 字节样本逐字节一致。

另保留两次进入 TLS 之前的 Wi-Fi 连接失败：一次终止最初的抢占测试，一次使超长响应检查未触达目标阶段。对应项目后续重测通过；这些失败不计为 TLS 拒绝或响应解析通过，也未作为本次修复已解决的问题。

## 资源与构建记录

16 次抢占样本停止后，系统堆占用均回到 1,200 字节。本轮记录的堆峰值为 71,568 字节；HTTPS 线程栈峰值为 5,944/8,192 字节，余量 2,248 字节。这些统计不覆盖全部独立内存池或所有未来工作负载。测试结束设备为 IDLE，无待启动录音和上传任务，测试录音保留。

构建基线提交为 `9ad3c0cabb7ed866037b9d5843aafa09a68ce0ac`，基于其上的工作区快照编译、刷写并验证；完整源码快照、差异、日志、ELF、map、配置和测量记录保存在本机 `.analysis/https-runtime-0.1.2/interruptible-io-v1/` 及 `interruptible-hardware-v1/`、`interruptible-hardware-v2/`。编译后仅补充文档，固件源码与已刷入快照一致。

- MCUboot 镜像摘要：`34d5ac4b240106d2bb9534d2ea4019181feeea951a28b2a88923055fba1545b8`，设备回读匹配。
- 签名镜像 SHA-256：`7be8cbb4145319e3689b8717e59f5f99038505210a620147f556e0031d41cdb9`。
- Flash 使用 817,452 字节，剩余 115,924 字节；静态 RAM 使用 448,358 字节，含既有堆栈预留。
- 相对上一镜像，Flash 减少 1,760 字节，静态 RAM 减少 48 字节；未缩小音频或 TLS 缓冲区，分区、外置 Wi-Fi 固件和配置参数保持一致，签名密钥路径仅随独立目录变化。
- 57 项主机测试通过，C 编译零警告，签名与分区校验通过。C 边界桩测试使用 ASan/UBSan；桩测试不验证密码库本身，证书和协议行为另经上述实机检查。

实机按键入口、STOP/关机竞态、DNS 阻塞边界、长时间运行、断点续传与掉电恢复仍需后续验证。
