# 录音文件 HTTPS 续传协议

本阶段增加文件内续传，仍通过 USB `AT+UPLOAD=YYYYMMDDHHMMSS:片段号` 发起。
每次任务先重新计算完整文件 SHA-256，并查询服务器确认的偏移，再继续上传。
文件身份由设备 ID、14 位会话 ID、片段号、总长度和 SHA-256 共同确定；同一个
设备／会话／片段不能静默替换成另一份内容。不改变手机同步标记，不删除录音。

## HTTP 请求

路径为 `/v2/devices/{device}/recordings/{session}/{segment}`。仅接受 HTTPS、
既有 Bearer 认证和固定长度请求；文件最大 8 MiB，每块最多 16 KiB。

所有请求带 `Authorization: Bearer …`、`X-Recording-Size: 总字节数` 和
`X-Content-SHA256: 完整文件的小写 SHA-256`。

1. `GET` 查询持久化检查点，请求体为空。未知文件返回 offset=0，已完成文件返回
   stored 和完整长度；无需重传文件。GET 本身不创建空的上传对象。
2. `PUT` 上传一块，额外带 `Upload-Offset`、`X-Chunk-SHA256` 和该块的
   `Content-Length`。只接受当前确认偏移，或与已保存内容完全一致的重复块；
   不接受跳过字节、重叠改写、重复长度头或 Transfer-Encoding。

设备使用 HTTP/1.1 keep-alive，在同一 TLS 连接中顺序查询和提交各块，不做流水线
并发，也不为每个块重新握手。取消仍由上传线程检查，清理后才允许录音开始。
最终 stored 回执明确关闭连接；部分块确认后保留连接供下一块使用。

成功响应 JSON 至少包括以下字段：

```json
{"status":"partial","size":60975,"sha256":"完整文件哈希","offset":16384}
```

`partial` 必须满足 `0 <= offset < size`；只有最终长度与整文件哈希都验证通过才
返回 `stored`，且 `offset == size`。查询成功为 HTTP 200，普通或重复块为 200，
首次发布最终文件为 201；设备对每份回执重新核对状态、长度、哈希和预期偏移。
完整文件哈希冲突、偏移冲突、坏块哈希和非法请求均失败，不自动覆盖已有对象。

## 持久化与恢复顺序

接收端每个对象使用部分数据文件和原子替换的 JSON 检查点。提交一块时依次：

1. 校验块长度与块哈希，在接收端提交锁下核对文件身份和偏移。
2. 追加数据，flush、fsync 数据文件。
3. 写新检查点临时文件，fsync，原子替换，再 fsync 目录。
4. 最后一块额外校验整文件哈希；原子发布最终 `.bin` 并 fsync 目录后，才返回 stored。

回复丢失时，下一次 GET 可发现检查点已经前进；设备不凭 `send()` 成功推断服务器
已保存。接收端重启后以检查点为准截掉额外尾部；检查点超过部分文件长度时明确
报错，不能猜测恢复位置。完整检查点已保存但最终发布未完成时，GET 会重新校验并
完成发布。整文件哈希失败时不发布，检查点重置为 0，允许从头再传。

这些规则依赖文件系统的 fsync/原子替换语义。接收端是单进程局域网测试服务，不
支持多个独立接收实例同时写同一目录。中断的 `.partial`／`.checkpoint` 是恢复数据，
不能当缓存删除；进程异常退出遗留的 `.checkpoint-*` 是未发布元数据临时文件，
不会被读取为已确认状态。原 `/v1` 整文件接收入口保留兼容。

## 设备状态和范围

`AT+UPLOAD?` 增加 `protocol:2`、`size`、`confirmed` 和 `resume_from`。
`sent` 是发送进度对应的绝对文件偏移，可能包含本轮尚未确认的块；`confirmed`
是最近一次验证过的服务器检查点，`resume_from` 是本次查询得到的起点。
已上传完整文件再次发起任务时可直接验证 stored；这些字段仅描述最近任务，
不是设备上全部文件的持久上传列表。

设备重启后仍需重新注入 Wi-Fi、接收地址、令牌及可信时间；服务器检查点可让
再次发起的同文件任务恢复。自动调度、设备端持久状态、自动重试和录音结束后自动
补传属于后续阶段，本阶段不会自动发起下一次任务。

验收需同时覆盖普通／增强录音打断、块中断、服务器已保存但回执丢失、接收端重启、
最终回执丢失与已完成对象查询，并核对真实发送范围、最终逐字节内容和资源回落。
已完成范围见 [续传验证记录](https-resume-v2-validation.md)。
