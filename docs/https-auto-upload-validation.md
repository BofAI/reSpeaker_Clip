# 空闲自动上传验证

验证对象是基于上游 v0.1.2 的 HTTPS 实验构建；功能范围见
[空闲自动上传](https-auto-upload.md)。本轮完成核心自动调度、断点续传、配置持久化
和故障恢复验证，未扩展手机配置界面、服务器周期对账或自动删除录音。

## 构建与主机测试

- 88 项主机测试通过，覆盖实际 C 配置读写及 CRC、失败处理、目录扫描、分页、
  抢占和持久上传状态。扫描样本包含 205 个会话、非规范目录和五位片段号。
- 编译无 C 编译器警告，签名验证通过；分区及 nRF70 镜像与基线一致。
- 实机镜像 MCUboot digest：
  `e02befe48d46f30db1146203a7581ea8e0faf4de96c32ce5eaa46048cfb91be4`。
- Flash 使用 826,292 / 933,376 B，剩余 107,084 B；静态 RAM 为
  448,214 / 450,560 B。与 `61fd143` 相比 Flash 增加 5,984 B、静态 RAM
  减少 160 B；配置改用约 448 B 堆分配，静态下降不代表总运行内存下降。

实测发现并修复了三项问题：HTTPS 命令表从已满的 40 槽扩为 48 槽，实际注册
45 个命令；扫描复用目录句柄以遵守原有 4 个 FAT 目录句柄上限；分页从每页三次
扫描改为一次扫描并裁剪已越过的会话。增加了对应回归测试。分页首个实测页面
耗时约 2.667 秒，后续随游标推进下降。

## 自动上传和恢复

| 场景 | 实机结果 |
|---|---|
| 批量待上传 | 初始 54 个片段中 51 个待上传，全部自动完成；跨 49 个待上传会话，无手动 UPLOAD 命令 |
| 普通录音抢占 | 上传已确认 16,384 B 后被录音打断，约 523 ms 观察到录音标志；结束后自动续传及上传新录音 |
| 增强录音抢占 | 同样在 16,384 B 检查点打断，约 599 ms 观察到增强录音标志；自动恢复成功 |
| 上传途中软件重启 | 本地持久进度仍为 0，服务器已有 16,384 B；重启恢复配置、重新校时，并按服务器进度续传 |
| 首次校时失败 | 返回超时并退避，未进入 HTTPS 请求；恢复校时接收端后自动成功 |
| 接收端返回 503 | 自动重试成功；请求间隔约 30.826 秒，包含 20 秒退避和扫描、联网时间 |
| 接收端停止 | 连接失败后退避；重启接收端后自动恢复 |
| 持久关闭后重启 | 配置仍在、自动上传关闭，观察窗口无 HTTP 请求 |
| 清除配置后重启 | 配置不存在、自动上传关闭，观察窗口无 HTTP 请求 |
| 实际关机再开机 | 用户拔 USB、关机后重新开机；启动 5.53 秒时确认配置恢复且自动调度开启，新文件自动上传成功 |

批量阶段因 USB 观察接口的 600 秒超时重开过两次 USB，期间短暂关闭并恢复自动
调度；未手工指定待上传文件。重启测试没有重新注入 Wi-Fi、接收端或 TLS 时间。
软件重启只经 Recovery 核对镜像并复位，未重新烧录或擦除。

自动测试结束后，61 个片段均核对了设备上传状态、服务端长度与 SHA-256，新增
录音均完成 Opus 解码检查；原有手机同步元数据未改变。

随后物理开关机测试新增第 62 个片段，15,988 B、215 帧、4.3 秒，服务端长度、
哈希与设备状态一致。开机后未手动注入配置、时间或上传命令。测试结束已持久关闭
自动上传并保留配置，Mac 测试接收服务停止。

## 运行资源及边界

冷启动空闲堆占用为 1,608 B，首次联网后稳定在 1,656 B，多文件处理后没有继续
增长；整轮观察到的堆峰值为 68,960 B，约 67.3 KiB。静态 RAM 数字包含预留堆等
区域，不能与该运行堆峰值直接相加来推算物理 RAM 使用。
物理开机后的完整 HTTPS 上传中，工作线程栈峰值为 6,992 / 8,192 B，剩余
1,200 B；这是已测路径的水位，并非所有输入的最坏值。

本轮未声称完成 SD 写入瞬间物理断电测试、8 MiB 文件最坏录音响应时间或电池续航
测量。已上传标记只代表上次确认成功，服务器后来丢失数据的周期对账不在本轮范围。
测试采用 Mac 局域网 HTTPS/SNTP 接收端，正式部署仍需对应的接收服务和配置入口。
