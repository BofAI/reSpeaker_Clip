# v0.1.2 HTTPS 运行时验证

基于已验证的外置 Wi-Fi 补丁、录音停止释放及 `AT+RES` 测量分支，使用
`production + https.conf + runtime.conf`。Station 替换 AP，USB 保留 CDC、关闭 MSC；
本轮不升级官方 v0.1.4，不改外置分区、bootloader 或网络核。

## 联网故障定位

1. 初次上传返回 `-22`，旧状态只显示 `connecting`。增加子步骤后确认 Wi-Fi
   关联、DHCP 和共存配置成功，错误位于 TLS socket 配置，而非 Wi-Fi 密码。
2. 公共测试证书为 P-256 ECDSA；原有配置主要支持 ECDHE-PSK，缺少 ECDSA。
   显式启用 PSA ECDSA 及 ECDHE-ECDSA 后，证书加载成功，进入握手。
3. 握手返回 `-113`。本 SDK 的 Newlib 中它是 `ECONNABORTED`，**不是** Linux
   的 `EHOSTUNREACH`（本 SDK 为 118）。不能使用宿主机的 errno 编号解释固件。
4. Mac 接收端记录 `NO_SHARED_CIPHER`。设备实际取得同网段 DHCP 地址、掩码和
   网关；ClientHello 诊断发现双方具有共同 ECDHE-ECDSA AES-GCM 套件及 ECDSA
   签名算法，但设备未发送标准 `supported_groups` 扩展。
5. SDK 的 `mbedtls/config_adjust_ssl.h` 仅通过旧版 `MBEDTLS_ECDH_C` /
   `MBEDTLS_ECDSA_C` 判定 `MBEDTLS_SSL_TLS1_2_SOME_ECC`，遗漏 PSA-only 配置。
   应用 CMake 在 TLS 1.2、PSA ECDH 启用时补充该兼容定义，保留原 PSA 后端，
   不修改共享 SDK。修复是否生效以实机成功上传为准。

诊断端口只解析 ClientHello 的套件、曲线和签名算法编号，不接收凭据或录音。
接收端日志仅记录 OpenSSL 握手失败原因码，不记录请求 URL、认证头或载荷。
`AT+UPLOAD?` 的 Wi-Fi 子步骤及 IPv4 信息在清理后保留用于定位，不代表当前在线。

## 提前取消及栈余量

曲线扩展修复镜像 `50b193b` 曾连续完成 20 次上传，60,975 B 文件逐字节
一致，并完整解码 812 个 Opus 包、16.24 秒。系统堆峰值 42,424 B，最终分配
1,200 B、空闲 80,624 B。但 HTTPS 栈高水位达 5,816 / 6,144 B，仅剩 328 B。

后续负面测试正确拒绝了未生效的证书时间，发送 0 B；紧接着立即取消下一任务时
设备失去响应，USB 软件恢复也超时。人工硬件复位后进入 Recovery，确认恢复入口
可用。代码发现准备阶段取消会在无线电尚未启动时调用 `wifi_off()`，继续向不存在
的无线电上下文发送共存复位命令。当前修复对已关闭接口直接结束清理，并将
HTTPS 栈增至 8 KiB；真实 C 函数的 ASan/UBSan 回归及 28 项 HTTPS 主机测试通过。
新镜像已完成证书时间拒绝、10 次立即取消及随后可信上传恢复：10 次均正常
取消、发送 0 B，清理后系统堆分配均为 1,200 B；未再次失去响应。恢复上传
60,975 B 与参考文件逐字节一致。新镜像的重复上传及栈峰值另行记录，不以旧
镜像的 20 次成功代替。

## 当前镜像实机结果：取消回归通过，上传稳定性未通过

- 首次可信上传、取消后的恢复上传和重复测试中的 7 次上传，共 **9 / 11 次常规
  上传成功**，成功文件均为 60,975 B，与已完整解码的参考录音逐字节一致。
- 两轮各设置 20 次、遇错停止：第一轮首个任务超时；第二轮前 7 次成功，第 8 次
  超时。均为 `last_error:-116`，发生于 TLS 连接阶段（同时包含底层 TCP 连接），
  发送 0 B。当前镜像**没有完成 20 次连续成功验收**，此前旧镜像的 20 次另行留档。
- 两次超时后都能正常清理、回应命令并返回 IDLE。10 次提前取消均通过，错误证书
  时间被拒绝，随后恢复可信上传成功。卡死复现路径的修复得到实机回归支持。
- 系统堆累计峰值 **42,424 / 81,824 B**，峰值对应余量 39,400 B；所有新工具
  在完成状态之后复读的清理后样本均为分配 1,200 B、空闲 80,624 B。
- HTTPS 栈高水位 **5,888 / 8,192 B**，剩余 **2,304 B**。与旧 6 KiB 镜像
  的栈高水位不同，不能把旧数值当作新镜像实测值。
- 最终设备为 **IDLE / normal**，CDC 开启，未录音、无活动上传。实验接收服务
  测试结束后关闭。资源数据只涵盖系统堆和线程栈，不覆盖独立 libc / Wi-Fi 池。

稳定性结论：立即取消卡死问题的回归通过，但整条上传链路尚未达到稳定验收。
两次连接超时的根因未确认，不能仅凭错误码归因于路由器、无线环境或 RAM。
下一步应对照 TCP/ARP 流量与设备网络步骤定位，并验证连接超时、无线共存及重连。
不将本轮标为整体 PASS，不以继续重复试验覆盖失败记录。

## 证据及回退

本地项目根目录下 `.analysis/https-runtime-0.1.2/` 保存各轮源码快照、差异、
镜像、ELF、map、最终配置、签名/分区报告和测量结果。`safe-cancel-build/` 为
上述修复镜像；此前 `psa-groups-build/` 以及 `build/`、`diagnostic-build/`、`tls-certificate-build/`、
`network-diagnostic-build/` 分别保留旧实验，不可混用镜像身份。
Wi-Fi 配置、令牌、私钥、收到的录音及原始测量保存在本机 `private/`，不推送。

回退到同布局、已验证的外置补丁应用，可使用
`.analysis/external-patch-runtime-0.1.2/images/clip-0.1.2-external-patch-signed.bin`，
SHA-256 为 `c859fa735db173f4b6dfdc657ce55553534e7e8ede4257432adc3edc5d65bacb`。
Recovery 为 overwrite-only，无自动回滚。回退到原内置补丁布局的旧应用时，
仍须先恢复原外置存储备份，不能仅刷应用。
