# v0.1.2 外置 Wi-Fi 补丁实机验证

结论：将 nRF7002 固件补丁移到外置 SPI NOR 后，应用内部 Flash 节省
86,680 B（84.65 KiB），剩余 87,348 B。设备启动、原有配对与录音读取、
普通／增强录音、暂停恢复、录音后 AP 和下载解码短测全部通过。
这是 Flash 空间验证，不代表 HTTPS、并发、长时间稳定性或续航验证通过。

参与链接，并启用补丁完整性检查和 2,048 B 分块读取。

## 分区与备份

外置 SPI NOR 总计 8 MiB。应用 OTA `0..0x0f0000`、网络核 OTA
`0x0f0000..0x130000` 不变。原 LittleFS 为 `0x130000..0x800000`，
迁移后为 `0x130000..0x7e0000`（109 → 107 个 64 KiB 块）。
末尾 `0x7e0000..0x800000` 的 128 KiB 用于 Wi-Fi 补丁；SD 录音存储不变。

1. 临时签名应用不挂载文件系统，不启动蓝牙、Wi-Fi 或录音；USB 写入默认锁定，
   固件禁止修改 `0x130000` 以下 OTA 区域。
2. 原区域完整读取两次，7,143,424 B 逐字节一致；每次分块传输均验证 CRC32。
3. 离线只读挂载源 LittleFS 2.1，创建缩小后的文件系统；重挂载后全部文件、
   目录和用户属性一致，共 3 个条目（含根目录）。挂载失败不会自动格式化源数据。
4. 使用当前 SDK 原始 `nrf70.bin`，87,046 B，SHA-256
   `6353a2d07319337a5aaa75af03f2303756496eda0e2bea53ef47bc2148f64e7f`。
5. 写前再次完整读取确认与备份一致；修改 108 个块，数据写入分块 CRC 校验，
   最后全量回读与目标镜像逐字节相同。

备份 SHA-256：`24cac3238f099521df7c3e0f133302467b5dd66d86a1c46d34f6524c016c99b4`。
迁移区域 SHA-256：`16446acf8e0f0b8e379f8d823d11cf39af3b1aa6767f4509d180b8ad960aafe2`。
含密钥和配置的备份、清单及迁移文件仅保存在本机 `private/` 下，目录 0700、文件 0600，
未提交或上传。工具操作及回退步骤见 `tools/flash_maintenance/README.md`。

维护程序首次查询无响应，定位到 SDK 的 CDC 轮询接收仍需显式启用 RX；
已修复并实机验证。发送开启流控，防止 FIFO 满时丢字节；最终设备树已核对。
所有数据分区写入均在该修正与双读备份通过之后执行。

## 实机结果

- 无需重新配对即可连接 `Clip C7BB`。迁移前 11 个录音会话仍可列出，旧会话
  `20261018074735` 可读取文件信息，书签和同步标记保留。
- 启动后首次 AP 成功；堆分配 37,456 B、峰值 39,536 B，与内置补丁版一致。
- 同一次启动内普通、增强、再次增强（含暂停／恢复）三组录音通过，停止后
  堆分配均为 1,280 B、空闲 80,544 B；增强场景累计峰值 68,584 B。
- 三组录音停止后 AP 启动 3/3 成功，另完成 AP 空闲测量；总计 5 次 AP 启动成功。
- 3 会话／4 文件：下载序号、长度、CRC32、完成文件数和完整 Opus 解码通过。
  共 2,439 包，48.78 秒，单声道音频。
- 暂停恢复后 STOP 报告文件数 1，而 LIST／下载实际为 2 的既有计数问题仍存在；
  两个文件都校验和解码通过，本实验未改动该逻辑。
- 结束为 IDLE／normal，AP、USB 数据模式和 SD 日志关闭。

主机 4 项测试通过，覆盖实际维护 C 代码（ASan／UBSan）、锁定／越界／CRC／
截断输入、离线迁移一致性及模拟恢复。
